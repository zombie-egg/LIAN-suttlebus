# 真机调试页面空白排查

2026年11月5日，手机端出现导航标题或底栏存在、正文空白的现象，模拟器可以显示业务页面。对照测试显示：独立的1105B最小静态页面仍空白；采用渲染兼容配置的1105C最小页面可以显示，用户已在手机确认进入首页后正文可以显示。

进一步在开发工具中捕获到实际启动错误：`module '@swc/runtime/_define_property.js' is not defined`，随后出现页面注册失败及 `wx://not-found`。这是增强编译生成的辅助模块未被正确注入的问题。已关闭增强编译和ES6转译，使用当前基础库可执行的原生JavaScript语法，重新编译后应用启动、首页加载和首次渲染日志正常，控制台错误数为0。

最终保留的配置：

- 显式使用 WebView 渲染及 glass-easel 组件框架。
- 补齐每个页面的独立JSON配置，固定正常首页为启动入口。
- 基础库配置统一为3.17.6；关闭增强编译、ES6转译和WXML压缩。
- 移除工具提示无效的glassEaselWebview配置，避免无效配置告警。
- 保留一个非默认的启动诊断页，方便后续设备兼容排查。
- 首页初始化异常仍显示连接状态，应用和页面有启动阶段日志。

用户已用最终新预览包确认“页面正常”。当前还在定位手机访问局域网后端的连接错误；不能将页面恢复显示等同于真机接口联调全部通过。

开发工具中跳过域名校验不会自动同步到普通手机预览。本地开发版在手机访问HTTP局域网接口前会准备开发调试状态；正式或体验版不会采用此处理，仍要求HTTPS合法域名。真机还会忽略从模拟器复制过来的127.0.0.1或localhost缓存地址。

连接失败时，开发版首页显示实际请求地址及原始微信网络错误。下一步应依据手机上的原始错误确认：地址是否为电脑局域网地址、手机和电脑是否同网段、微信是否允许访问局域网、请求是否仍受合法域名校验限制。

9组自动化测试和静态资源检查已通过；手机完整联网验证仍需现场确认。

## 2026-11-06 真机接不上演示后端

这次不是页面渲染问题，而是手机到后端这条链路没有通。现场检查到：

1. 电脑上 3100 端口没有进程监听，`curl http://127.0.0.1:3100/api/health` 直接失败。真机调试扫码时后端必须是运行状态。
2. 后端原来只监听 `127.0.0.1` 和 `.env` 里写死的 `LIAN_LAN_IP`。电脑换 Wi-Fi/热点后旧地址失效，手机仍被指向旧地址；在 macOS 上这种失效地址甚至会“监听成功”但不产生可用 socket。
3. 电脑当前在 iPhone 个人热点网段 `172.20.10.x`。如果扫码的手机就是热点主机，iOS 热点主机访问热点客户端经常被系统拦截；如果手机走蜂窝网络，更不可能访问到电脑私网地址。
4. HTTP 局域网地址还受两层微信限制：开发版需要在手机上打开“开发调试”跳过域名校验；iPhone 需要允许微信访问“本地网络”。

已做的修复：

- 后端开发模式启动时自动枚举并监听当前所有私有 IPv4，`.env` 地址过期只警告，不再让整个服务退出。生产模式仍然只监听回环。
- `npm run mini:connect -- --lan` 写入 `deviceApiCandidates`（当前所有私有网卡），小程序请求主地址超时后自动切换下一个，并记住可用地址；域名校验错误只报一次，不做无谓重试。
- 新增 `npm run demo:phone`：同步地址、启动或检查后端、分别从本机和局域网请求 `/api/health`，并打印手机浏览器自测地址。
- 首页错误面板显示实际地址、候选地址、原始错误、手机自测地址和四步排查提示；“我的→后端连接”增加“恢复默认地址”。
- 新增 `npm run demo:web`，手机浏览器可直接看网页演示，用来区分“网络问题”和“微信限制问题”。

### 三分钟判定顺序

1. 电脑运行 `npm run demo:phone`，确认本机和局域网两行都是 ✅。终端不要关。
2. 手机浏览器打开终端打印的 `http://电脑IP:3100/api/health`。
   - 打不开：网络问题。把电脑和手机都连到同一个 Wi-Fi 路由器；不要让电脑连手机热点、手机再用蜂窝网络。确认电脑防火墙未拦截 3100。
   - 能打开：网络层没问题，问题在微信侧，进入第 3 步。
3. 手机微信右上角“…”→“开发调试”打开，重新进入小程序；iPhone 再到“设置→微信→本地网络”打开并重启微信。
4. 微信开发工具重新编译后再扫码真机调试。仍失败时首页面板会显示微信原始错误（`request:fail ...`），据此判断是域名校验、超时还是网络不可达。
5. 必须跨网络演示时运行 `npm run demo:tunnel`，脚本会生成临时 HTTPS 地址并写入小程序配置并自检；当前网络若屏蔽 `trycloudflare.com`，脚本会明确报错，此路不可用。

结论：真机 demo 的前提是“手机浏览器能打开电脑的 `/api/health`”。这一步不过，改小程序代码没有意义。
